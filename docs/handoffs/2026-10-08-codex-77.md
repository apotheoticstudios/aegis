## Public API
- `BriefSchedule`: Codable/Sendable/Equatable configuration and persisted state. Takes explicit opening hour/minute, zone, local/fixed zone policy, optional duration history, input-age window (default 15 minutes), attempt timeout (default 10 minutes), and previous brief timestamp. Exposes `lead`, `opening(on:calendar:)`, `state`, `job` and `lastBriefAt`.
- `ScheduledBriefJob`: deterministic persisted attempt ID, opening, target civil date, absolute deadline and acknowledged input timestamp.
- `ScheduleState`: idle, refreshing, generating, cancelling, deferred(reason:), backoff(until:).
- `ScheduleEvent` and `step(_:_:calendar:)`: event timestamps inject the clock; the calendar is injected and its zone overridden by the persisted explicit zone. All events must be serialized by the driver.
- `ScheduleAction`: refreshSources, startGeneration, publishBrief, cancelJob, keepPreviousBrief, publishDeferred and refused. An empty list means no effects; refusal uses exactly `already_generating` for mapping to `CoreResponse.refused(code:)`.

## Decisions made (and why)
- Refined the suggested event shape with `sourcesRefreshed(jobID:inputTime:at:)` so generation cannot race source collection or use an expired/future snapshot. Refresh starts at opening minus lead; generation starts when its fresh snapshot is acknowledged. The formula's extra minute provides refresh/scheduling headroom.
- Added publication, cancellation and refusal effects to make the future driver behavior explicit. Refresh and cancellation reserve the same single slot as generation. A watchdog/sleep cancellation never frees the slot until `jobFinished` acknowledges termination, so even a hung worker cannot overlap a retry.
- Added `resume(Date)` for restart recovery **only after the driver confirms all previous workers have terminated**. It treats an interrupted attempt as failed, keeps the previous brief and retries after backoff. If a worker survives/reconnects, decoding retains its reservation and the driver can continue its normal completion stream without `resume`.
- `jobFinished(.completed)` must mean the entire result was validated by AegisCore, not merely that model text arrived. Persist transitions before starting work, and persist `publishBrief` plus its final schedule state in the same database transaction. This makes crash recovery safe at the publication boundary.
- Input freshness is checked both before generation and before publication. The scheduler stores only metadata, never brief or collected text. AegisCore retains the actual last checked `StoredBrief`.
- Nearest-rank p95 uses the last 20 successful published generation durations. Negative/non-finite measurements are ignored. Failed/cancelled attempts do not bias readiness estimates. Exponential retry delay starts at 60 seconds and caps at one hour; a successful publication resets it, and a manual request may bypass it.
- DST gaps use Calendar `.nextTime`; folds use `.first`. Today/tomorrow calculations use calendar days, including a lead that crosses midnight. Wake and stale pending work coalesce to the current day rather than replaying missed days. Completed civil dates are deduplicated across travel and bounded to the last 20 dates.
- Power conditions defer new work, including a model start after power changes during refresh. Already running generation may finish. Clearing both flags resumes pending work once; sleep requests cancellation.
- No ADR: this issue already authorizes the pure scheduling module; no architecture, privacy, safety, existing IPC contracts or dependencies changed. Implementation plus public documentation and scenario tests exceeds the suggested 400-line PR target.
