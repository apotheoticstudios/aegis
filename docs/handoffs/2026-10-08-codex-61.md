## Public API
- `ReaderBase.openReadOnly(_:busyTimeout:body:)` scopes connection lifetime. Original rollback-journal stores use URI `mode=ro`; WAL stores use protected private copies, including their WAL, opened with `mode=rw` for recovery. Both set the busy timeout and `PRAGMA query_only = ON`; neither uses immutable mode.
- `SQLiteConnection.query(_:bindings:onRow:)` streams typed `SQLiteRow`/`SQLiteValue` cells; `execute`, `columns`, and `require` support readers. Connections are synchronous and not Sendable; statements and connections close on success and failure.
- `ReaderBase.scan(_:reader:now:since:busyTimeout:onItem:)` passes the window to a reader callback, which emits `ReadItem.event(Event)` or `.problem(ReadProblem)`. Without `onItem`, `ReadResult` collects items; with it, arrays stay empty and only `SourceStatus` counts accumulate.
- `SourceStatus.Code` preserves all six Stage 0 strings. `StoreUnavailable`, `SQLiteError.isLocked`, and `UnknownSchemaError` carry statuses or schema names without SQL/row content. Programmer/query errors propagate, matching Python's OperationalError behavior.
- `ReaderBase.cocoa`, `cocoaSeconds`, `number`, `skewFlags`, and `makeEvent` preserve epoch bounds, numeric types, the ten-minute allowance, whole-second event timestamps, and one observation with the contract-derived Event ID.

## Decisions made (and why)
- **Behavior deviation:** copy every WAL store, including stores with both sidecars present. Testing the literal Python approach against macOS SDK SQLite demonstrated that `mode=ro` modifies an existing `-shm` file. Copying every WAL store meets the issue's stronger requirement that reading never change files beside the source; a test compares all source-file bytes with sidecars both present and absent. This adds disk-copy work and can return busy for a continuously changing live WAL store after three attempts.
- Private directories have mode 0700 and copied files mode 0600. Source and WAL size/mtime stamps are checked before/after each copy, with three attempts and stale WAL removal. Symlinks are resolved so a writable snapshot cannot point back into the source and the main store's actual WAL is included.
- Swift uses camelCase names and typed callbacks/results instead of Python dictionaries/generators. The helper rejects non-finite Cocoa seconds, and schema checking rejects absent tables even when no required columns are specified.
- Internal per-call `StoreAccess` closures allow deterministic permission, SQLite-open, and copy-race tests without global mutable state or concurrency exceptions.
- No ADR added: system SQLite and this reader layer were explicitly specified by #61. No architecture, third-party dependency, safety-system, or privacy-policy change is introduced.
