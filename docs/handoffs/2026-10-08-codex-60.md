## Decisions made (and why)
- Foundation filesystem indexes and a fixed-buffer external merge sort replace Python's SQLite merger. The input builder spools bounded rendered variants and hashed-thread reply times, then selects with a bounded heap. Fixed-width file indexes and incremental registered-file cleanup avoid directory-sized native allocations, including for many distinct owner threads. This handles arbitrary arrival order without an unbounded thread map or retaining the input stream. Private scratch directories/files are removed on return or error; no new dependencies, network, or content logging.
- Darwin Foundation bridges required per-iteration autorelease pools: before this fix the 200,000-event builder peaked at 135 MB; afterwards it peaked at 28.6 MB versus 28.8 MB for the 12-event baseline. The internal helper is conditionally compiled on Objective-C platforms and calls the closure directly on Linux. This is the only platform-specific runtime accommodation, necessary to meet the bounded-memory requirement on macOS; no Apple-only framework is imported.
- Swift cannot represent malformed draft priorities/field types in the contract `Brief`; `toBrief` throws `invalidDraft` for those instead of preserving untyped fields for Python's later validator. Invalid citations, empty text/IDs, negative omission, and reversed windows remain available to contract validation. Attempted action fields are stripped as in Python.
- JSON extraction additionally respects quoted/escaped braces, avoiding loss of otherwise valid model answers. The Python test expectations are preserved.
- Python's SQLite-specific query-plan assertion is not portable to a Foundation implementation; Swift instead tests fixture twins and multi-run external sorting. Fixture integration expectations are reproduced through generated expected JSON, without the SQLite readers.
