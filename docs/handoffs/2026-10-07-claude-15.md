## Decisions made (and why)
- Claude took this while Codex's allowance reset (owner: "just keep working, codex can check them after"). The issue was relabelled agent:claude; Codex reviews afterwards.
- The output matches the generator's expected files exactly:
  - events field by field, with `now` set to the fixture time;
  - problems by code, source and record (their notes are free text).
- Statuses are `ok`, `no_data`, `not_found`, `permission_denied`, `busy` and `unreadable`.
  - An unknown layout raises `UnknownSchemaError`; `read.py` reports it as `unknown_schema` and goes on to the other source.
  - A missing database is `not_found`, not `no_data`, so a path that moved on a new macOS version shows up.
- Notifications that were requested but not delivered yet are skipped as `not_delivered` and read on a later run, the same delivery rule as the probe.
- Messages:
  - Tapbacks (2000–3007) are skipped.
  - A value above 1e14 is nanoseconds; below that it's seconds.
  - Future times are flagged `clock_skew`, the generator's general rule.
  - A message in several chats gets the one with the lowest chat id.
- `since` filters in SQL. Real runs default to 24 hours, so the trial doesn't read whole histories.
- Streaming with `on_item`: 20,000 messages use under 4 MB of Python memory; keeping the events would take about 30 MB.
