## What changed
- Added `BriefChecks.check`: raw draft + exact `BriefInput` + event evidence + trusted window/model/time metadata → `Result<CheckedBrief, BriefRejection>`. Success holds the publishable brief and total `droppedItems`; failure carries a fixed reason code only.
- Added lenient `Briefing.convert`, preserving structural-drop counts, disallowed-field evidence, and urgent citations from malformed items. `toBrief` remains a compatibility conversion, now dropping malformed items; publishing must use the draft/conversion gate to retain provenance.
- Structural defects and items with any citation outside the input or missing event evidence drop the entire item. More than two total drops, attempted action fields, urgent planted orders, surviving-item budgets (7 items/3 urgent), missing citations, oversized or multiline/control text, and remaining contract errors reject the draft.
- Added fallback that returns the previous brief unchanged with a timestamp/reason-only panel status, including the case with no previous brief.
- Added evaluator budget overflow/noise counts and `budgetPass`; all affect `passed`. `loadBudget(labelsData)` reads `brief_budget` or defaults to production constants. Explicit `important` labels override legacy urgent/needs-reply inference for noise scoring.
- Added 17 gate tests and 8 evaluator-budget tests. Updated compatibility tests for lenient conversion and grouped recall citations so the 90% recall test stays within the new budget.

## Decisions made (and why)
- Implemented the issue's supplied post-review decisions without changing `Contracts/`, XPC messages, dependencies, prompts, or stored serialization.
- Model fields use a strict allowlist: top-level `items`, item `text`, `priority`, and `event_ids`. Any extra field is treated as an attempted action, including empty fields and nested fields in malformed items. This prevents unfamiliar action/tool field names from slipping through a denylist.
- Steering checks run before citation drops. Urgent citations from structurally malformed items remain available to the gate so dropping cannot hide a planted-order attempt.
- Budget limits apply to the surviving publishable items after allowed drops. Missing/non-array top-level `items` rejects the draft rather than becoming an empty successful brief; an explicit empty items array remains valid.
- Production limits are fixed constants. Evaluation callers pass `BriefEvaluator.loadBudget(labelsData)` as `budget`; malformed, null, incomplete, or negative supplied budgets throw. The held-out budget was checked for consistency; prompts and sealed labels were not changed or tuned.
