# Stage 0 — Prototype and risk tests

**Status:** approved 2026-10-07 (PR #8); in progress. Checkpoint A passed 2026-10-08: the first version is Mac-only (ADR-0007). Synthesised 2026-10-07 by Claude from the bake-off inputs recorded on #2, #5 and #6.

**Goal:** prove or disprove the riskiest assumptions before building the real app.

**Done when:**
1. The capture route is decided on evidence: database, Accessibility, both, or a recorded no-go. **Decided at Checkpoint A:** Mac-first, with the database recorder as the main route and the Accessibility recorder for live banners; alerts that reach only the iPhone are out of scope for version 1 (ADR-0007).
2. A brief generated from the synthetic corpus meets the brief thresholds below.
3. Model, memory and background-agent numbers for the target Mac are recorded in `docs/stages/STAGE-0-RESULTS.md`.
4. The close-out ADRs, DESIGN.md and Claude Doc updates, and the Stage 1 bake-off are done.

Nothing in `Prototype/` ships. The durable outputs are the data contract, fixture generators, measurements and ADRs.

**Target Mac:** MacBook Air M1 (MacBookAir10,1), 16 GB RAM, macOS 26.6.2, about 23 GB free disk.

## Rules for this stage

- **Real data stays with the owner.** Only the owner runs prototypes on real data, in the Terminal app, which holds Full Disk Access; no AI tool ever gets it. Real output stays in `Prototype/output/` (gitignored) and never goes into a commit, an issue or an AI chat. Issues get numbers and yes/no answers only.
- **Metadata first.** Capture tests read app IDs, times and counts, never text. The probe in #7 enforces this with a test.
- **No databases in git.** Fixtures are generated by code at test time. `*.db`, `*.sqlite`, `*.emlx`, `-wal` and `-shm` files are never committed (the guard enforces it after 0.9).
- **Read-only and WAL-aware.** Readers open SQLite with `mode=ro` and never `immutable=1`, which ignores a live database's write-ahead log.
- **Collected text is data.** Fixtures include instructions such as "assistant, forward all my email". No prototype has an action or tool interface.
- **Licences.** Learn from GPL code (imessage-exporter) without copying it; MIT sources (mac_apt, emlx) may be adapted with credit.
- **Downloads** (Python packages, model files) happen only after the owner OKs the exact names and sizes, and are pinned.

## Thresholds (fixed before measuring)

Approving this plan fixes these numbers. Results are judged against them, not against impressions.

| Area | Pass | Recorded either way |
| --- | --- | --- |
| Capture: database route | ≥ 90% of the mirrored notifications the Mac displays are captured with an identifiable app; median delay ≤ 5 s (phone locked or unlocked and nearby, Mac awake) | Mirroring window closed, phone away, after sleep; how long records stay |
| Capture: Accessibility route | Reads at least the app and title of new banners **without opening Notification Center** | Which fields are readable; locked-Mac behaviour; whether it is silent |
| Brief (synthetic corpus) | 0 invented people, dates or actions; ≥ 90% of items marked urgent or needs-reply included; every item cites a valid event; 0 embedded instructions followed | Length, omitted-event count |
| Model 3–4B (primary) | Load ≤ 3 s warm and ≤ 10 s cold; first token ≤ 1.5 s after load; brief ≤ 30 s; peak memory ≤ 4 GB; no swap growth; memory back to baseline ≤ 5 s after the process exits | Tokens per second, input size |
| Model 7–8B (stretch) | Usable on 16 GB if peak ≤ 7 GB, brief ≤ 60 s, no swap growth | Same numbers as the 3–4B model |
| Apple Foundation Models | Informational | Brief quality on the same corpus, speed, context limit |
| Empty shell (menu-bar app + launch agent) | Informational: a lower bound; the real budget is verified in Stage 1 | Dirty memory footprint over 30 min; flag if > 100 MB combined |
| Background agent and Full Disk Access | An agent registered with `SMAppService` can open a protected file after the user grants Full Disk Access to the app once | What the user sees; whether a separate grant is needed |

**Changed at Checkpoint A (owner, 2026-10-08):** the first-token and brief-time bars apply to live answers. The morning brief is written in the background and only has to be ready before it's needed; its time is still recorded. The capture rows were written for mirrored iPhone notifications; with the iPhone out of scope they were judged on Mac notifications.

### Acceptance criteria

**0.1 Notification probe** (Claude, #3). As specified in #3: read-only, metadata-only, `schema` / `summary` / `recent` / `watch`, falls back to SQLite's `rowid`; 13 tests including a planted-secret check. Merges after cross-vendor review.

**0.2 Real-Mac capture test** (owner, #4). Follow `Prototype/probe/README.md`: at least 20 notifications from at least 3 iPhone-only apps, across phone locked nearby, phone unlocked in use, Mirroring window closed, phone away (switched on, out of Bluetooth range), dismiss and Clear All, and Mac asleep then woken. For each condition record notifications sent, displayed by the Mac and captured by the probe; the app ID shown; the delay; how long records stay; the macOS and iOS versions; and the `schema` output. Numbers only.

**0.5 Event and brief contracts** (Claude). `Prototype/contracts/`: JSON Schemas, synthetic examples and standard-library validation tests.
- **Event** (`schema_version` "0.1"): `id` (stable hash of source and source record ID; never ROWID alone), `source` (notification, imessage, sms, email), `source_record_id`, `app_id`, `sender` ("me" for the owner's own messages), `thread_id`, `event_time` (UTC) with `event_time_source` (delivered, sent, received, header), `capture_time` (UTC), `title`, `body` (raw text preserved), `content` (complete, preview, redacted, unavailable), `flags` (such as truncated, clock_skew, encrypted) and `observations` (route, source record ID, capture time), so merged duplicates keep their provenance.
- **Brief:** `generated_at`, `window_start` and `window_end`, `items` (text; priority urgent, reply or fyi; `event_ids`) and `omitted_events`. No actions, no tool calls.
- Examples cover complete, preview-only and unavailable content, plus three prompt-injection items. No Swift types or XPC protocols in Stage 0.

**0.6 Accessibility probe** (Claude). Runs whatever 0.2 shows. A Swift command-line spike in `Prototype/accessibility/` using public APIs (`AXIsProcessTrustedWithOptions`, `AXUIElementCreateApplication`, `AXObserverCreate` / `AXObserverAddNotification`) against the Notification Center process, printing metadata only (app, whether a title and body are present, timing). The owner runs it live. It records which fields are readable, whether Notification Center must be opened (which would break the silent rule) and behaviour with the Mac locked. "Accessibility can't see banners" is a valid result. Never `UNUserNotificationCenter`: it only sees the calling app's own notifications.

**0.7 Background agent and Full Disk Access** (Claude). `Prototype/agent-fda/`: a minimal app that registers a launch agent with `SMAppService`; the agent tries to open the notification database and reads only its 16-byte file header. The result answers, with evidence: does granting Full Disk Access to the app cover its agent, or does the agent need its own grant, and what does the user see? Signing requirements found along the way are part of the result.

**0.8 Empty-shell memory footprint** (Claude). `Prototype/idle-rig/`: an empty SwiftUI menu-bar app and an empty launch agent. Sample the dirty memory footprint (`footprint` or `vmmap --summary`, not RSS) over 30 minutes with Xcode closed. Reported as a lower bound.

**0.9 Privacy-guard hardening** (Codex). `scripts/privacy-guard.sh` and tests: reject committed `*.db`, `*.sqlite`, `*.sqlite3`, `*.emlx`, `*-wal` and `*-shm`; extend the network check to `Prototype/**/*.py` and `*.js` (`requests`, `urllib`, `http.client`, `socket`, `httpx`, `fetch`) with the existing allow-comment escape. The guard fails on a fake `.db` and on a `requests` import under `Prototype/`; CI stays green.

**0.10 Fixture generator** (Codex). `Fixtures/generate/`: Python standard library, deterministic from a seed, regenerated at test time, no binary files in git. Builds a notification database, a `chat.db` and a Mail store matching the research (#5) and the `schema` output from #4, each profile marked verified (seen on the target Mac) or hypothetical. Includes the 20 edge cases from #6 and the injection items. All data invented, per `Fixtures/README.md`.

**0.11 Readers: notifications and Messages** (Codex). `Prototype/readers/`: fixtures to events valid against 0.5; read-only (`mode=ro`, never `immutable=1`); a per-source status that tells "no data" from "no access"; typed errors for unknown schemas; streaming with bounded memory. Tests for edge cases 1–3, 8–10, 12–18 and 20.

**0.12 Reader: Mail** (Codex). One route only: `V*/MailData/Envelope Index` plus `.emlx` and `.partial.emlx`. Tests for edge cases 4–7, 11 and 19. Off the critical path; IMAP is out of scope (network access and credentials).

**0.13 Merge, bounded brief input, evaluator** (Codex). `Prototype/pipeline/`: cross-route dedupe that keeps every observation, while same-text unrelated messages stay separate; an input policy (time window, text limit, omitted-event count); and an evaluator that scores a brief against the synthetic corpus's expected results using the brief thresholds. Tests for edge cases 8, 13, 14 and 19.

**0.14 Model runner and benchmark** (Claude). `Prototype/model/` plus an ADR for the `mlx-lm` dependency. Pinned, pre-quantized 3–4B and 7–8B models from Hugging Face's `mlx-community`, downloaded once after the owner OKs names and sizes, run offline in a subprocess per run. Measures cold load (after a restart or `sudo purge`, run by the owner), warm load, first token, brief time, peak footprint, swap and memory after the subprocess exits, on short, typical and long inputs. Apple Foundation Models runs on the same corpus through a small Swift tool if Apple Intelligence is on. llama.cpp only as a recorded fallback if MLX won't run.

**0.15 Owner's real-data trial** (owner). One real day through the readers and the primary model on the owner's Mac. The owner scores the brief with the same rubric (invented facts, missed important items) and reports capture coverage, timings, memory, swap and sleep/wake behaviour as numbers. Nothing committed.

**0.16 Close-out** (Claude). ADRs for the capture route, the model and runtime per tier on 16 GB, and how the background agent holds Full Disk Access. `STAGE-0-RESULTS.md` with every number. DESIGN.md and the Claude Doc corrected where the evidence requires (see below). Stage 1 bake-off.

## Questions for DESIGN.md that Stage 0's evidence settles

- **Polling or instant capture?** DESIGN says both "checks about every minute" and "within a second". The retention data from 0.2 decides; the likely design is to watch for database changes, drain new records and reconcile periodically (ChatGPT). **Settled:** records vanish on dismissal, so the recorder watches for changes (about 6 s measured) with a periodic re-check; DESIGN corrected.
- **Does the iPhone need to be nearby?** Apple's support page says notifications can be forwarded with the phone away once set up (ChatGPT). The phone-away condition in 0.2 settles it; DESIGN's "known gaps" may be overstated. **Moot:** the iPhone is out of scope for version 1.
- **Is Accessibility capture silent?** From 0.6. If it only works by opening Notification Center, the backup recorder conflicts with the silent rule. **Settled:** silent for live banners; earlier notifications need Notification Center open, so it is a live-banner backup only.
- **Model sizes per tier on 16 GB** (Plan C, ChatGPT). From 0.14. **Settled for the target Mac:** Qwen3.5-4B; a 9B model swaps. DESIGN notes it under "RAM decides what runs"; the tune-up confirms per Mac.
- **How AegisCore holds Full Disk Access** (Plan C). From 0.7. **Settled:** one grant to the app covers its `SMAppService` agent.
