# ADR-0019: Keyword-only wake before speech transcription

Status: implemented for owner review in #245. Owner request: Siri-like “Hey Aegis”, then “Yes?”, then capture the question (2026-10-15).

The previous listener transcribed every voice-like segment and searched its text for a wake phrase. Room noise could keep those segments open for twelve seconds. This also did not meet the owner's requirement that words be transcribed only after the wake phrase.

Use the native sherpa-onnx 1.13.8 keyword spotter with the Apache-2.0 GigaSpeech 3.3M keyword model (2024-01-01, int8 encoder/joiner). Its decoder is constrained to the token sequence for HEY AEGIS and, when configured, the owner’s one-word English custom name; the wrapper returns a Boolean, never arbitrary speech text. ONNX Runtime 1.28.1 is MIT-licensed. Both macOS static frameworks are SHA-256 pinned to the upstream package manifests. The model archive is checksum pinned in the packaging script; only model files and the fixed keyword are shipped. Unigram token scores exported from the pinned model let the runtime configure a custom wake name in memory, without writing the name to any file. Notices are bundled with the app. Downloads occur only during builds, never at runtime. No Python, external app, access key or server is required.

While idle, microphone frames go exclusively to the keyword worker. It uses one CPU inference thread on a utility queue, with bounded pending buffers. No idle audio is forwarded to or buffered for Apple's question transcriber. A match pauses capture, opens the panel and says “Yes?”. Only after acknowledgement finishes does question transcription start. At the owner’s request (2026-10-16), pauses do not end listening or clear the conversation. After acknowledgement and each reply, capture remains available until the owner says the exact command “End Conversation” (case and punctuation ignored). That command is handled locally, clears the visible conversation, and returns to keyword-only mode. Mentioning the phrase inside a longer question does not trigger it. Individual stalled recognition sessions are reset without expiring the conversation. The former ten-minute panel-history expiry is also removed; the existing twenty-exchange display bound remains. The owner should wait for “Yes?” before asking; pre-acknowledgement words are deliberately discarded.

The keyword model stays loaded only while the owner enables hands-free mode. Switching it off releases the model and stops the microphone. Playback/thinking pauses keyword and question capture. Missing keyword assets fail closed with a visible error, without falling back to background transcription. Existing Apple on-device recognition is used only for the question. Numeric room-level calibration prevents constant ambient noise being mistaken for an endless question. Nothing logs or persists microphone audio or recognized text.

This is Mac-only app/runtime code; AegisKit and shared XPC contracts are unchanged. Tests use invented speech and deterministic noise, verify repeat wakes and negative phrases through the real keyword model, and verify that no pre-wake audio enters the transcription buffer. Microphone use against real surroundings remains an owner validation step. Keyword-model memory and throughput are measured separately from voice synthesis; the app-wide idle budget still applies.

Validation limitation: synthesized “Hey Friday” and repeated “Hey Aegis” trigger with a custom name configured; synthesized “Hey Atlas” did not trigger, even with alternative tokenizations and higher sensitivity. Keep the conservative default threshold rather than increasing false wakes. Custom English names remain configurable, but their accuracy depends on the model; “Hey Aegis” always remains enabled. These synthetic checks do not establish accuracy for every voice or room. The final app-wide idle footprint still needs owner measurement.
